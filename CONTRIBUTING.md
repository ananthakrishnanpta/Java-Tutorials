# Contributing

Thank you for helping improve Java Mastery. This repository is designed for learners, so clarity and correctness matter as much as cleverness.

## Before opening a change

1. Choose the smallest lesson that fits the topic.
2. Keep examples focused: one idea per program whenever possible.
3. Use meaningful names and add a short explanation of any non-obvious behavior.
4. Compile every changed example with the JDK version documented by the project.
5. Check links in the affected README files.

## Lesson format

Each lesson should explain the mental model first, provide a runnable example, include an edge case or common mistake, and end with practice prompts. Avoid copying an API reference; show the decision a Java developer needs to make.

## Pull requests

Describe what learners will gain, list the files changed, and include sample output for new examples. Do not mix unrelated formatting changes with instructional changes.
